# AI benchmark

Цель измерения — сравнить локальные кандидаты на двух ограниченных текстовых задачах, не блокируя MVP. Базовый контроль — провайдер `mock`. Кандидаты для отдельного запуска: квантованные Qwen3 4B и Qwen3 8B через совместимый runtime.

## Набор данных

Подготовить минимум 30 синтетических русскоязычных заявок:

- 20 полных примеров для четырёх категорий;
- 5 неоднозначных примеров, где неизвестные поля должны остаться `null`;
- 5 некорректных/непрофильных текстов;
- вариации дат, времени, населённых пунктов, длительности и ограничений.

Отдельно подготовить не менее 20 задач ранжирования с фиксированными наборами из 8 синтетических предложений и экспертным top-3.

## Задача 1: JSON-разбор

Ожидаемая схема: `category`, `scheduledAt`, `durationHours`, `locality`, `workDescription`, `constraints`. Неизвестные поля равны `null`.

Фиксировать:

- долю валидного JSON без repair;
- exact match категории и населённого пункта;
- MAE длительности;
- точность даты/времени;
- false fill rate: долю придуманных значений в неизвестных полях;
- p50/p95 задержки, timeout и ошибки runtime.

## Задача 2: ранжирование 8 предложений

До модели детерминированно убрать несовпадающие категорию, регион и доступность. Модель получает только допустимые варианты.

Фиксировать NDCG@3, совпадение top-1, долю объяснений без выдуманных фактов, p50/p95 и число нестабильных повторов при одинаковом входе. Сравнить с обычной сортировкой backend по подаче, цене и рейтингу.

## Протокол

1. Зафиксировать Mac/CPU/GPU/RAM, runtime, модель, quantization, context, temperature и seed.
2. Выполнить один warm-up, затем минимум 3 повтора каждого примера.
3. Не включать время загрузки модели в latency запроса, но записать отдельно cold start и пик памяти.
4. Сохранять только синтетические входы и обезличенные метрики.
5. Имитировать timeout/невалидный JSON и подтвердить fallback на mock/ручную форму.
