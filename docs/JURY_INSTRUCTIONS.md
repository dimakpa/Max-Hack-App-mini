# Инструкция для жюри

## Открыть работающий сценарий

1. Откройте бота [@t52_hakaton_max_bot](https://web.max.ru/51922339) в MAX.
2. Откройте Mini App из бота.
3. Создайте заявку от заказчика: укажите категорию, дату, адрес объекта, объём и ограничения; выберите предложение и отправьте заявку.
4. Ссылка на Mini App: https://max-ai.5.63.152.157.sslip.io/ . Проверочный маршрут: `https://max-ai.5.63.152.157.sslip.io/health`.

## Проверка API и двух ролей

Техническая проверка двух ролей воспроизводится локально без паролей и без production-секретов:

```bash
cp .env.example .env
docker compose up --build
```

Откройте `http://localhost:8080`. В demo-режиме доступны синтетические роли:

- `customer` — заказчик;
- `dispatcher-a`, `dispatcher-b`, `dispatcher-c` — диспетчеры разных модельных поставщиков.

Для прямой проверки API задайте заголовок `x-demo-user` со значением одной из этих ролей. Полный порядок запросов, методы и ожидаемые ответы приведены в `DATA-API.yaml`; контракт — в `openapi.yaml`.

В опубликованном MAX роли определяются серверной проверкой `x-max-init-data`; demo-заголовок там не работает. Токены, пароли и webhook-secret не включены в репозиторий.

## Данные и ограничения MVP

Поставщики, техника, цены, рейтинги, отзывы и каталог являются синтетическими данными MVP. Продукт не принимает оплату и не бронирует технику. Ограничения описаны в `docs/KNOWN_LIMITATIONS.md`.
