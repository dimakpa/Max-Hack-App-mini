# QA checklist

## Сборка и окружение

- [ ] `docker compose up --build` поднимает db, backend, bot и frontend.
- [ ] `GET /health` возвращает 200 через публичный reverse proxy.
- [ ] `GET /api/meta` показывает четыре категории, зону пилота и `syntheticData: true`.
- [ ] `npm test` и `npm run build` завершились успешно.

## Заказчик

- [ ] Текст длиной менее 10 символов получает ошибку валидации.
- [ ] Черновик содержит адрес объекта и объём работ; они редактируются и сохраняются.
- [ ] Геометка объекта сохраняется вместе с заявкой и открывается на карте из карточки заказа.
- [ ] Заказчик может приложить до четырёх материалов: JPG/PNG/WebP до 3 МБ или PDF до 5 МБ.
- [ ] Неподдерживаемый тип, слишком большой файл или пятый материал получают понятную ошибку; диспетчер видит материалы после отправки заявки.
- [ ] Подбор за пределами зоны пилота возвращает понятную причину.
- [ ] Подбор исключает занятую технику и показывает не более пяти вариантов.
- [ ] Повторный `POST /api/orders` с тем же `idempotencyKey` не создаёт дубликат.
- [ ] Заказчик не может смотреть или менять чужую заявку.
- [ ] Отзыв доступен после `COMPLETED` и только один раз.

## Диспетчер

- [ ] Диспетчер видит заявки и технику только своего поставщика.
- [ ] Нельзя выполнить недопустимый переход статуса.
- [ ] Откат требует причину и не отменяет завершённую заявку с отзывом.
- [ ] Нельзя скрыть карточку техники с активной заявкой.
- [ ] JPG/PNG/WebP до 3 МБ сохраняется; другой тип или больший файл получает контролируемую ошибку.

## MAX и production

- [ ] Mini App открывается из бота MAX на мобильном устройстве и в web-версии.
- [ ] При `DEMO_AUTH=false` заголовок `x-demo-user` не даёт доступ.
- [ ] Валидный `x-max-init-data` проходит серверную проверку; некорректный — отклоняется.
- [ ] Секреты не находятся в git, презентации, README, OpenAPI или test fixtures.
- [ ] При перезапуске сохраняются данные PostgreSQL и volume `equipment_uploads`.
