# Соответствие пакета требованиям онлайн-этапа

| Требование | Артефакт и проверяемое свидетельство |
| --- | --- |
| Работающий сценарий в MAX | Публичный Mini App указан на слайде 1; финальная приёмка из бота MAX — пункт чек-листа владельца. |
| Презентация в PDF | `deliverables/ТехЗаказ_презентация_онлайн_этап_финальная.pdf`, 12 слайдов. |
| Ссылка, репозиторий, commit, API | Слайд 1, README, `DATA-API.yaml`. Пользователь подставляет username бота и hash последнего commit перед отправкой. |
| Понятная продуктовая ценность | Слайды 2–7: сегмент, проблема, путь, редактируемый черновик, подбор, подтверждение и статусы. |
| Проверка гипотезы | `docs/INTERVIEW_GUIDE.md`: скрининг, вопросы, опрос, способ фиксации. Результаты не сфабрикованы. |
| Техническая реализация | Слайды 8–9, README, Docker Compose, миграции, тесты, OpenAPI. |
| Собственный API | `openapi.yaml` (OpenAPI 3.1), `DATA-API.yaml`, `testdata/api-fixtures.json`. |
| Воспроизводимый запуск | README: Docker-команда, порты, окружение, восстановление. `docs/RUNBOOK.md`. |
| Проверяемость и качество | `docs/QA_CHECKLIST.md`, unit/integration/E2E-тесты, health-check, контролируемые ошибки. |
| Безопасность данных | `docs/SECURITY_CHECKLIST.md`, README и слайд 9: секреты в окружении, production-проверка WebAppData. |
| Честность демо | `docs/KNOWN_LIMITATIONS.md`, README и слайды 3, 5, 6, 9, 10: синтетический каталог, mock-парсер, отсутствие оплаты и реальных результатов пилота. |
