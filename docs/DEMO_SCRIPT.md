# Demo script на 3–5 минут

## Подготовка

Открыть `http://localhost:8080`. Убедиться, что выбрана роль `Анна, заказчик` и виден признак тестовых данных.

## Сценарий

1. Нажать `Описать задачу`. Оставить подготовленный текст про автокран в Чебоксарах и нажать `Подготовить черновик`.
2. На экране проверки показать извлечённые поля и возможность исправить каждое. Нажать `Найти предложения`.
3. Сравнить 3 предложения: техника, поставщик, смена, время подачи, рейтинг и объяснение. Выбрать первое и отправить заявку.
4. Открыть `Мои заявки`: заявка `Новая`. Переключить тестовую роль на `Илья, Поставщик А`.
5. Открыть заявку и нажать `Связаться с заказчиком`. Под ролью Анны запрос отображается в заявке и подтверждается кнопкой `Уже связались`.
6. Снова открыть заявку поставщиком: нажать `Подтвердить`, `Начать работы`, затем `Вернуть статус`. Указать причину и убедиться, что заявка снова подтверждена, а причина есть в истории.
7. Повторно начать и завершить работы. Вернуться к `Анна, заказчик`, открыть завершённую заявку и сохранить отзыв. После отзыва возврат статуса недоступен.
8. Открыть `Уведомления`: показать события `dry-run`, то есть реальный обмен frontend → backend → PostgreSQL/outbox → bot adapter без токена MAX.

## Одна дополнительная ошибка

Начать ручную заявку, указать `Казань` и выполнить подбор. Ожидается пустое состояние с пояснением границы пилота и кнопкой изменения параметров. Альтернатива: попытка второго отзыва через API возвращает контролируемый `409 REVIEW_EXISTS`.

Реальная доставка в MAX в этом локальном показе не заявляется: для неё нужны публичный HTTPS, токен и настройки бота.
