# Security checklist

Это чеклист MVP, не заявление о соответствии законам и не pentest.

## Проверено автоматически

- [x] Внешние JSON-входы валидируются Zod, длины строк ограничены.
- [x] SQL параметризован; динамические значения не подставляются в запросы строковой конкатенацией.
- [x] Статусная машина, роли, принадлежность поставщику, доступность, один отзыв и идемпотентность покрыты тестами.
- [x] MAX HMAC покрыт позитивным, tamper, duplicate key и expiry тестами.
- [x] Production dependencies: `npm audit --omit=dev` — 0 известных уязвимостей на 18.09.2026.
- [x] Полный `npm audit` после обновления Playwright/Vitest — 0 известных уязвимостей на 18.09.2026.
- [x] `.dockerignore` и `.gitignore` исключают `.env`, локальные token-файлы, логи и артефакты тестов.
- [x] Docker build выполнен без локальной LLM и токена.

## Проверено вручную

- [x] Demo-режим включается отдельной переменной и Compose-конфигурацией; default backend — `false`.
- [x] Без demo-заголовка или подписанного `WebAppData` защищённый API не предоставляет неявную роль.
- [x] `initDataUnsafe` не используется как доказательство личности.
- [x] CORS принимает только перечисленные `FRONTEND_ORIGIN`.
- [x] API скрывает внутренние ошибки и не возвращает токены/пароли.
- [x] Пользовательский текст React выводит как текст, `dangerouslySetInnerHTML` не используется.
- [x] Deep link содержит только неприватный ID заказа; телефон в MVP не запрашивается.
- [x] Rate limit включён для `/api`.
- [x] Контейнеры backend/bot запускаются непривилегированным пользователем `node`.

## До публичного запуска

- [ ] Проверить threat model и провести независимый review/pentest.
- [ ] Хранить bot token и DB credentials в secret store с ротацией.
- [ ] Настроить TLS, WAF/rate limits на ingress, trusted proxy/IP policy и webhook hardening.
- [ ] Ввести onboarding/role binding реальных `max_user_id`, админский аудит и отзыв доступа.
- [ ] Настроить backup/restore, retention, шифрование и redaction централизованных логов.
- [ ] Добавить условия использования, политику обработки данных, контакт поддержки, модерацию и удаление незаконного контента.
- [ ] Повторить dependency/container scan в CI и подписывать образы.
- [ ] Проверить актуальные требования MAX непосредственно перед публикацией.
